# 🛠️ Quartz 運用・管理マニュアル

このノートは、Quartzを運用し、テクニカルディレクターとしての「思考の現像所」を維持するためのカンニングペーパーです。

## 🚀 毎日使う「3つの魔法」（デプロイ手順）

Obsidianで記事を書いたり、設定を変更したりした後は、ターミナルで以下のコマンドを順番に実行します。

Bash

```
# 1. Quartzフォルダに移動（パスは自分の環境に合わせて調整）
cd C:\Users\yokom\OneDrive\デスクトップ\my-library

# 2. 変更内容をすべてカゴに入れる
git add .

# 3. 変更に名前をつけて保存する
git commit -m "update: 記事を追加"

# 4. 世界（GitHub）へ送り出す
git push origin v4
```

## 🗺️ サイトの「設計図」一覧

「何かを変えたい」と思った時に開くファイル。

|**目的**|**ファイル名**|**編集内容の例**|
|---|---|---|
|**サイト全体の基本設定**|`quartz.config.ts`|サイト名(`pageTitle`)、言語(`locale`)、色|
|**画面のレイアウト**|`quartz.layout.ts`|サイドバーの項目、グラフ表示の有無|
|**公開する記事本体**|`content/` フォルダ|Obsidianで編集する `.md` ファイル|
|**自動公開の仕組み**|`.github/workflows/deploy.yml`|GitHub Actionsの動作設定（Node.jsのVerなど）|

## 🎭 記事ごとの「演出設定」（Frontmatter）

ノートの冒頭（1行目）に書くことで、そのページの振る舞いを決められます。

Markdown

```
---
title: ブラウザ上のタイトル（ファイル名と変えたい時）
draft: true   # trueにすると、サイトには表示されない「下書き」になる
tags:
  - 演出
  - 技術
---
```

## 🚨 困った時のトラブルシューティング

「反映されない」「エラーが出る」時のチェックリスト。

1. **GitHub Actions の確認**
    
    - GitHubのリポジトリの **[Actions]** タブを見て、「赤のバツ」が出ていないか確認。
        
2. **キャッシュの削除**
    
    - ブラウザで `Ctrl + F5` を押して、強制的に最新の状態を読み込む。
        
3. **ローカルプレビュー**
    
    - ターミナルで `npx quartz build --serve` を実行し、`http://localhost:8080` で正しく映るか確認。
        
4. **ブランチ名の確認**
    
    - `git branch` を打ち、今いる場所が `v4` であることを確認。

## 💡 テクニカルディレクターとしての心得

- **「動かない」は成長のチャンス：** エラー文は、システムがあなたに送っている「ヒント」です。
    
- **完璧よりデプロイ：** `draft: true` を活用し、未完成の思考もどんどん「現像（ビルド）」していきましょう。
    
- **技術を比喩で語る：** あなたにしかできない「演出的な視点」を、技術解説に添えることを忘れずに。
